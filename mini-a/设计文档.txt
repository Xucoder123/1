步骤三：实现前端界面与基本功能
描述：
在这一阶段，我将提供一个简化的微信小程序前端示例，包含代码编辑器、提交按钮、输出显示区域，并集成基本的撤销功能。由于微信小程序不支持直接运行C代码，需通过后端API实现编译和运行。


以下是该微信小程序 C 语言编译器项目的设计思路：

### 整体目标
开发一个微信小程序，实现 C 语言代码的在线编辑、编译和运行功能，同时提供代码编辑历史记录管理。
有输入框、输出框、撤销返回（历史缓存）、可折叠
### 架构设计
整个项目分为前端小程序和后端服务器两部分：
- **前端（微信小程序）**：负责提供用户界面，接收用户输入的代码，发送编译请求，并显示编译和运行结果。
- **后端（Node.js 服务器）**：接收前端发送的代码，使用 Docker 容器化的 GCC 编译器进行编译和运行，将结果返回给前端。

### 详细设计

#### 前端（微信小程序）
1. **项目配置**
    - `mini/app.json`：配置小程序的页面路径、窗口样式等基本信息。设置导航栏标题为“C 语言编译器”，并定义了窗口的背景颜色、导航栏颜色等样式。
    - `mini/project.config.json` 和 `mini/project.private.config.json`：配置小程序的开发环境，包括 appid、编译类型、库版本、开发工具设置等。`project.private.config.json` 中的配置会覆盖 `project.config.json` 中的相同字段。
2. **应用初始化**
    - `mini/app.js`：在小程序启动时，检查并创建日志目录，确保日志文件有存储的位置。同时，调用合法的 API 进行网络请求，示例中使用 `wx.request` 发送 POST 请求。
3. **页面设计**
    - `mini/pages/index/index.js`：实现了代码编辑页面的逻辑。
        - **数据管理**：使用 `data` 对象存储用户输入的代码、代码历史记录、编译输出结果、当前历史记录索引以及历史记录的折叠状态。
        - **事件处理**：
            - `handleInput`：处理用户输入的代码，更新 `data.code`。
            - `addToHistory`：将新的代码添加到历史记录中。
            - `undo` 和 `redo`：实现代码编辑的撤销和重做功能。
            - `compileCode`：发送编译请求到后端服务器，并处理响应结果。
            - `selectHistory`：选择历史记录中的代码版本。
            - `toggleHistory`：切换历史记录的折叠状态。

#### 后端（Node.js 服务器）
1. **服务器搭建**
    - `mini/server.js`：使用 Express 框架搭建 HTTPS 服务器，监听 443 端口。
2. **请求处理**
    - 定义 `/compile` 接口，接收前端发送的代码。
    - 将用户代码写入临时文件 `temp.c`。
    - 使用 Docker 容器化的 GCC 编译器执行编译命令 `gcc temp.c -o temp.out`。
    - 如果编译成功，运行生成的可执行文件 `temp.out` 并获取输出。
    - 将编译和运行结果返回给前端。

### 安全性和稳定性考虑
- **SSL 证书**：使用 HTTPS 协议确保数据传输的安全性。
- **错误处理**：在前端和后端都进行了详细的错误处理，如文件写入失败、编译错误、运行时错误、网络错误等，确保用户能够得到明确的错误提示。
- **日志记录**：在小程序启动时创建日志目录，方便后续的日志记录和问题排查。

### 扩展性考虑
- **代码历史记录**：实现了代码编辑的历史记录管理，方便用户回溯和恢复代码版本。
- **用户交互**：提供了撤销、重做、历史记录选择等功能，提升用户体验。

通过以上设计思路，项目实现了一个完整的 C 语言代码在线编辑、编译和运行的功能，同时考虑了安全性、稳定性和扩展性。
